# MESAFARTAI — Regras e Etapas do Projeto

## ETAPA 1 – KICKOFF, DOCUMENTAÇÃO, ARQUITETURA E BANCO DE DADOS

Nesta primeira etapa do projeto MESAFARTAI, o grupo deverá organizar a estrutura inicial necessária para o desenvolvimento do sistema.

Deverá ser criado um repositório público no GitHub com o nome `PROJETO-MESAFARTAI`, contendo a documentação e os arquivos iniciais do projeto.

O arquivo `README.md` deverá apresentar o título oficial do projeto, uma descrição resumida da solução, seu alinhamento com a ODS 2 da ONU e a identificação dos integrantes do grupo.

Também deverá ser criada a pasta `docs`, contendo este arquivo `regras.txt` e o arquivo `escopo_projeto.md`. O escopo deverá apresentar o problema de negócio, o público-alvo, as intenções que serão tratadas pelo sistema, os dados coletados durante a conversa e o prompt utilizado para a criação do logotipo.

O projeto deverá possuir uma identidade visual, com um logotipo que represente a união entre alimentação, acolhimento, tecnologia e Inteligência Artificial.

Nesta etapa também deverá ser criado o arquivo `src/database.py`, desenvolvido em Python utilizando SQLite3. Esse arquivo será responsável pela criação do banco de dados `mesafartai.db`, contendo as tabelas de usuários, doações e matches, além da carga inicial com dados de teste de ONGs e doadores.

Ao final desta etapa, o repositório deverá estar organizado, documentado e com o banco de dados funcionando corretamente, estabelecendo a estrutura inicial para o desenvolvimento das próximas etapas do MESAFARTAI.

### Registro da execução

O script `src/database.py` foi executado com sucesso. A verificação do banco confirmou a existência das tabelas `usuarios`, `doacoes` e `matches`, além dos registros de teste de duas ONGs e dois doadores.

## ETAPA 2 – MOTOR NLU E TRAVA DE THRESHOLD

Nesta etapa, foi desenvolvido o módulo `src/nlu.py`, responsável pelo processamento de linguagem natural e pela classificação das intenções das mensagens dos usuários.

O motor utiliza TF-IDF para transformar os textos em representações numéricas e o algoritmo Random Forest para classificar as mensagens. O modelo foi configurado com 80 árvores de decisão e threshold de confiança de 0,60.

Foram definidas quatro categorias de intenção:

- `cadastrar_doacao`
- `solicitar_alimentos`
- `consultar_status`
- `fora_de_escopo`

O mecanismo de fallback retorna uma mensagem solicitando que o usuário esclareça se deseja doar alimentos ou solicitar doações para uma ONG. Mensagens classificadas como `fora_de_escopo` também recebem fallback.

### Registro dos testes

O módulo foi executado sem erros. Nos quatro testes realizados, a mensagem sobre doação de bananas foi classificada como `cadastrar_doacao`, com confiança exibida de 0,93. As mensagens sobre solicitação de mantimentos, receita de bolo e texto confuso receberam fallback.

A execução demonstrou o funcionamento do classificador e da resposta de fallback para os casos testados.
